Getting started

Pointe is a voice layer for your coding agents. You talk; it listens, reports what each session did, sends your requests to the right one, and reads permission prompts out so you can answer them by voice. The sessions do the work and keep their context.

This page takes you from nothing to your first call, in about 5 minutes. You need macOS, a coding agent (Claude Code 2.1.224 or newer, Codex 0.160 or newer, or OpenCode v2), Google Chrome, headphones, and one model key (a free Google key is enough to start). Everything Pointe installs, and how to remove it: Install.

1. Install

With Claude Code, in Terminal:

claude plugin marketplace add https://github.com/ballerine-io/pointe.git && claude plugin install pointe@pointe

In the Claude desktop app's Code tab, type the two commands instead: /plugin marketplace add https://github.com/ballerine-io/pointe.git, then /plugin install pointe@pointe.

With Codex or OpenCode (no Claude Code needed), in Terminal:

curl -fsSLO https://eng.ballerine.com/pointe/install.sh
bash install.sh

It says what it will do and asks first, checks the release against a SHA-256, and needs no sudo (The standalone install). Then run pointe setup in a new terminal: the same steps as below, in the terminal, and then it sets up Codex and OpenCode for the voice (Codex, OpenCode).

2. The first setup

Open a new Claude Code session, so the plugin loads, and run:

/pointe:setup

The session first says "Pointe is installed. Run /pointe:setup to finish." Setup then:

  1. Checks your Mac and installs what is missing: uv, and about 180 MB of Python packages on the first run.

  2. Asks one question: "Start with Free start?". Free start runs every role on one Gemini key. Say no to see the other setups (Models and setups).

  3. Opens the vendor's key page, and a Mac window for the key. The key goes from that window to your macOS Keychain; it never passes through the chat. Setup checks the key with one small call.

  4. Starts your first call. Allow the microphone in the tab that opens, press Connect, and say "hello". Pointe answers that it hears you, and setup says "Pointe heard you. You're set up."

Your phone, the Mac app and faster setups come after, as optional extras: /pointe:setup phone, /pointe:setup apps.

3. The first call

The call is a page in Chrome, on 127.0.0.1. In any Claude Code session you want to reach, run:

/pointe:voice

If Pointe is not running, this starts it and opens the page. Without Claude Code, pointe open does the same, and a Codex or OpenCode session joins with pointe join codex or pointe join opencode, run in its folder. Press Connect, and talk:

  • "What is this session doing?"
  • "Tell it to run the tests and fix what fails."
  • "What did it decide about the retry logic?"

The page shows the conversation as it happens, what Pointe heard as you speak, and every pending permission request with its exact text and Approve and Deny. You can type instead of talking, and correct a line that was misheard.

When a session asks for permission, Pointe reads the request out and waits. A plain "yes", said right after the read-out, approves it. "No" denies it. A request Pointe cannot read out whole (unknown programs, sudo, several lines) waits for a tap on the page, the iPhone app or the terminal. The exact rules: How it works.

To end the call, hang up on the page. To stop Pointe entirely, run /pointe:stop (or pointe stop).

4. Joining a session

A session you join to the voice is a coding-agent session that Pointe can hear about and talk to. It keeps running where it is, in its own terminal, with its own context. Joining it means three things:

  • Pointe reads it. It follows the session's transcript and keeps short notes on its goal, its state and what it decided. When the session finishes a turn, Pointe tells you what you need to know.

  • Pointe can send to it. A request you speak goes to that session as a message, after a check that it matches what you said.

  • Pointe holds its permission prompts. While a call is up, a joined session's prompts come to the call to be read out. When you hang up, they go back to the session's terminal.

One call can hold many joined sessions. One is active: what you say goes to it unless you name another. Say a session's name to switch ("switch to billing"), or to address it once ("billing, run the tests"). The others stay quiet, except for "finished" and "needs approval".

A Claude Code session is named after its folder, plus its git branch when the two differ (shop/main). Name it yourself with /pointe:voice --name billing, or rename it on the page.

Join an OpenCode or Codex session pointe join opencode or pointe join codex (Harnesses)
Join sessions you already run, without typing in them Say "connect to the session about the pentest", or use Add sessions on the page or in the apps (Add sessions)
Start a new session Say "start a new Codex session in shop", or use New session (Start a new session)
Join a session on another machine Make that machine a node (Machines)
Take a session off the voice /pointe:leave in it, say "close billing", or use × on the page
Stop all voice /pointe:stop, or pointe stop

Commands

Command Does
/pointe:setup guided setup: keys, first call, phone
/pointe:voice join this session to the voice (starts the daemon if needed)
/pointe:open open the page again
/pointe:leave take this session off the voice (or say "close billing" or "close all except billing", or use × on the page)
/pointe:stop stop all voice
/pointe:doctor what runs here, what is missing, and the one key that would help most
pointe local fully local: download and start the local models, no keys (details)
pointe local voice voice stays on your Mac: local ears and mouth, the brain in the cloud gets text only (details)
/pointe:voice-review ask a session what happened in the last call
pointe update the standalone install: the newest release, checked against its SHA-256 (details)
